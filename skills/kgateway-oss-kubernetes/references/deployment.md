# Deployment decisions

Read the selected release's [Helm guide](https://kgateway.dev/docs/envoy/latest/install/helm/) and [Gateway setup](https://kgateway.dev/docs/envoy/latest/setup/) before installing. Inventory existing Gateway API CRDs, kgateway CRDs and controller, GatewayClasses, releases or GitOps owners, namespaces, listener addresses, certificates, and traffic. Render release-matched CRD and controller charts; do not replace shared Gateway API CRDs or an existing gateway installation as a side effect of an example. Use the customer's deployment owner for updates.

For traffic, use the selected release's [Gateway and listener guide](https://kgateway.dev/docs/envoy/latest/setup/listeners/http/) and [HTTPRoute guidance](https://kgateway.dev/docs/envoy/latest/traffic-management/) to map hostnames, listener ports, `allowedRoutes`, parent references, backend references, and any `ReferenceGrant`. Use TLS secrets and DNS names the customer controls. A listener address is a reachable endpoint only after the platform assigns and exposes it.

For policy, use [kgateway policies](https://kgateway.dev/docs/envoy/latest/about/policies/) and the selected feature guide. `TrafficPolicy`, `ListenerPolicy`, `BackendConfigPolicy`, and `GatewayExtension` attach at different scopes; check target references and inheritance before rendering. The OSS [GatewayExtension](https://kgateway.dev/docs/envoy/latest/about/custom-resources/) can connect customer-provided external auth, global rate limit, or processing services. Do not assume a configured policy is enforced until the relevant Gateway or route reports status and traffic proves the outcome.

For upgrades, inspect the [operations guidance](https://kgateway.dev/docs/envoy/latest/operations/) and release notes. Preserve Helm release ownership, CRD compatibility, traffic continuity, certificates, and rollback scope. A migration from another controller needs an inventory of Ingress or Gateway resources and a request-based cutover check.
