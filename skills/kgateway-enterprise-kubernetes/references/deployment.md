# Deployment decisions

Follow the selected line's [Helm installation](https://docs.solo.io/kgateway/latest/install/helm.md) and [licensing](https://docs.solo.io/kgateway/latest/install/licensing.md) guidance. Inventory the current Gateway API and kgateway CRDs, Enterprise CRDs, controller, Helm or GitOps owner, GatewayClasses, listeners, routes, and proxies before rendering. Render release-matched CRD and controller charts. On an authorized empty cluster, install Gateway API CRDs compatible with the selected Enterprise release before creating Gateway API resources; do not silently skip this dependency. If they already exist, check their version and owner before changing them. Review changes to shared CRDs, webhooks, RBAC, and GatewayClasses. Prefer the documented Secret or mounted-file license path to an inline Helm value; verify actual entitlement without printing the key.

For routing, use standard Gateway API `Gateway` and routes with the [Enterprise setup guides](https://docs.solo.io/kgateway/latest/setup/index.md). Check listener hostnames, ports, `allowedRoutes`, parent references, backend references, and cross-namespace grants. Preserve addresses and certificates through a migration. Existing OSS policy resources can remain valid; use the selected release's [policy model](https://docs.solo.io/kgateway/latest/about/policies/index.md) to decide when `EnterpriseKgatewayTrafficPolicy` or `EnterpriseKgatewayParameters` is needed.

For built-in auth and global rate limiting, consult [external auth](https://docs.solo.io/kgateway/latest/security/extauth/index.md) and [global rate limiting](https://docs.solo.io/kgateway/latest/security/ratelimit/global/index.md). Confirm the service and CRDs are installed, the policy attaches to the intended route or Gateway, and the requested identity or descriptor is used. Use an existing customer-provided external service when that is the requested architecture; the Enterprise controller does not require every policy to use a built-in service.

For a [developer portal](https://docs.solo.io/kgateway/latest/portal/index.md), plan the published API, exposure, [OIDC login](https://docs.solo.io/kgateway/latest/portal/frontend-setup/login.md), and role mapping before provisioning API credentials. Authentication is required for subscription and self-service credential management; verify a reader and administrator against their intended permissions. Do not treat the portal as the gateway controller's administrative UI.

For an OSS-to-Enterprise migration, follow the [migration guide](https://docs.solo.io/kgateway/latest/install/migrate.md) and test traffic before retiring the old controller. Do not uninstall shared OSS CRDs or the namespace as cleanup. For an upgrade, follow release-matched operations and keep a scoped rollback.
