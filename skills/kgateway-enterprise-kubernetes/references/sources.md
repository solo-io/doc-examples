# Sources and edition boundary

Use the installed or selected Enterprise release. The [product index](https://docs.solo.io/kgateway/llms.txt) locates supported lines; use that line's page index and full pages. Start with [quickstart](https://docs.solo.io/kgateway/latest/quickstart.md), [Helm installation](https://docs.solo.io/kgateway/latest/install/helm.md), [licensing](https://docs.solo.io/kgateway/latest/install/licensing.md), and [API reference](https://docs.solo.io/kgateway/latest/reference/api/index.md). Check exact chart values, CRDs, and release notes before writing commands or resource fields.

The [Enterprise comparison](https://docs.solo.io/kgateway/latest/about/overview.md) separates shared OSS features from Enterprise features. The [OSS migration guide](https://docs.solo.io/kgateway/latest/install/migrate.md) documents which existing resources continue to work and when Enterprise kinds are useful. The [Gateway API specification](https://gateway-api.sigs.k8s.io/) and [releases](https://github.com/kubernetes-sigs/gateway-api/releases) govern standard resources; check the selected Enterprise release's compatibility before changing shared CRDs.

The public [FE Enterprise kgateway workshop](https://github.com/solo-io/fe-enterprise-kgateway-workshop) provides examples, not a support contract. Select the relevant lab and verify pinned versions, fields, chart values, and secrets against the customer's release. [kgateway.dev](https://kgateway.dev/llms.txt) is useful for shared upstream behavior, but does not establish Solo-specific values or licensed features. For LLM or MCP routing, consult [agentgateway.dev](https://agentgateway.dev/docs/) and the applicable Agentgateway documentation.
